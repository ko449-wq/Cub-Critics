# Contributing to Cub Critics

The Gladiators team works in small, reviewable changes so other members' work is preserved.

1. Create a branch named `feature/<topic>`, `fix/<topic>`, or `docs/<topic>` from the latest `main`.
2. Keep the change focused on one issue or SRS requirement. Avoid unrelated formatting rewrites.
3. Run the static preview locally and check desktop/mobile sizes, keyboard navigation, filters and dialogs.
4. Open a pull request that states purpose, related requirement IDs, screenshots if UI changes, and tests performed.
5. Request teammate review; merge only after approval and conflict resolution.

## Commit convention

Use concise prefixes like `feat:`, `fix:`, `docs:`, `test:`, and `chore:`.
